# IVCS RT — 20260915: raw DICOM, configurable views and 3D contours

- Added validated raw Implicit VR Little Endian DICOM import without a Part 10 header. Other ambiguous headerless encodings are rejected with a readable error.
- Series with repeated spatial positions are partitioned by acquisition number (or acquisition time if number is absent). The selector lists each acquisition independently. Original study/series/frame/SOP UIDs remain intact; storage keys and contour sessions distinguish acquisitions. Original DICOM bytes are archived unchanged.
- Tested the supplied phantom ZIP in an isolated temporary library: 14 selectable acquisitions, 13 with three slices and one with two. Selected acquisitions loaded and archived independently. The supplied phantom is NOT included in distribution packages.
- New 1+2 layout: larger axial panel at left, sagittal/coronal at right by default. Drag the vertical separator or focus it and use left/right arrows; double-click resets 65/35 distribution.
- Every panel in 1+2 and 2x2 can select axial, coronal, sagittal, active-plane detail, controls or 3D contours. Image modes include reference, aligned registered secondary, blend, side-by-side comparison, checkerboard, splits and difference. Registered images retain physical reference-plane alignment. Standard reference MPR retains its crosshair navigation. One reference axial panel provides the contour editor; other image panels are visualization views.
- 3D contours use visible ROI masks in DICOM physical millimetres. Optional selected-ROI-only filter and independent 3D opacity. Drag to rotate freely, wheel to zoom, right-drag to pan; Reset 3D view fits the surfaces.
- Surface meshes follow exact voxel boundaries (including holes), merging coplanar faces rather than modifying or smoothing the stored contours. Thin/coarse slice data can therefore show steps. This is a visualization, not a dose model.
- Three.js loads only on first 3D selection. Mesh generation runs in a disposable worker and is debounced while contours change. There is no perpetual animation loop; rendering is event-driven. Hidden layouts unmount the view, terminate pending workers and dispose meshes, materials, controls and the WebGL context. A hidden browser document pauses mesh work and rendering. No 3D computation occurs when no 3D panel is selected.
- English and Spanish labels included; MIT and Three.js dependency notices included in About.

Validation: TypeScript check, production build and 61 automated tests passed. Browser tests passed for the real phantom selection/import, splitter dragging, secondary image selection, 3D rotation/zoom, idle-frame stability, 2x2 use and cleanup on returning to axial. Windows portable smoke test is recorded separately in release.json. macOS/Linux packages remain untested on native systems.

This folder is a separate build from the earlier 20260915 package. The date code remains 20260915. Only the procedural Luciano Bello demo ships in these packages.


## Nested surfaces and silhouettes

The 3D opacity slider now spans 0–100%. Each visible ROI is rendered into its own depth-tested layer; transparent layers are accumulated independently of draw order, preventing rotation-dependent occlusion of nested structures. Colors are blended for illustrative visualization rather than physical volume rendering. At 100%, normal opaque depth occlusion applies.

A screen-space silhouette in each ROI's color remains visible even at 0% fill opacity. This is a projected outline, not a voxel wireframe, and does not alter contour masks or exported geometry.

Render targets are reused and disposed with the panel. Rendering remains event-driven, with no continuous animation while idle. More visible ROIs require more rendering passes.

Validation: GPU tests with three nested surfaces, four camera orientations, reversed insertion order, zero-opacity outlines and opaque depth; browser checks for 1+2/2x2 layouts, opacity control, idle rendering and cleanup.
