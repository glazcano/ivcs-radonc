# IVCS RT — Oblique acquisition support (20260916)

This document describes the initial oblique implementation. The subsequent [acquisition update](ACQUISITIONS_20260916.md) adds irregular parallel spacing, Enhanced frames and floating intensities and supersedes the corresponding restrictions below.

Regular parallel oblique, sagittal, coronal and reversed acquisitions can now be imported. A regular affine slice displacement is supported, including consistent in-plane drift. Nonparallel planes, duplicate positions, nonuniform spacing and inconsistent dimensions are rejected rather than silently interpreted as a regular volume.

## Geometry and precision

DICOM Image Position Patient, Image Orientation Patient and Pixel Spacing define a voxel-to-patient LPS affine. The actual inter-slice displacement defines the third basis vector; its inverse is used for sampling. In-plane direction cosines are checked for orthonormality. There is no assumption that native slice progression follows patient Z.

The viewer creates an axial reconstruction with isotropic spacing equal to the smallest native pixel/normal-slice spacing. Its extent encloses all native voxel support corners, so oblique ends are not cropped. Trilinear interpolation preserves local intensity bounds; values are rounded once into the application's existing signed 16-bit intensity representation. This does not increase the acquired resolution. Half-voxel boundary support uses edge extension; samples outside it use an explicit validity mask and black padding. Derived DICOM declares signed padding when its value is not also a valid image intensity.

No silent reduction of resolution is performed. The reconstruction has a 128 Mi-voxel / 4096-per-axis limit; larger grids report a memory error. The displayed source and derived volumes both consume memory. Reconstruction runs in a disposable worker at import, reports progress and is saved with the study. Reopening does not recompute it. Already-compatible axial images bypass reconstruction.

## Registration

The original native volume is retained. Manual/landmark fusion samples that native volume directly in patient coordinates, avoiding a second interpolation through the axial display grid. Automatic rigid registration also uses native images for both fixed and moving volumes. Rotation centers are physical volume centers in all three axes. Rigid transforms still map moving patient LPS to reference patient LPS; reconstruction does not change the Frame of Reference.

## Identity, storage and export

Reconstruction creates deterministic new Series/SOP UIDs from source identifiers, geometry and reconstruction parameters. Original DICOM files are archived byte-for-byte under the study, using the original source Series UID for association. Reimporting identical data with renamed files keeps the same reconstructed identifiers and contours.

For a reconstructed primary image, DICOM ZIP includes original images, derived axial images and RTSTRUCT referencing the derived images. Derived images use explicit VR little endian, signed 16-bit calibrated intensities, updated geometry, DERIVED/SECONDARY/MPR identification and Source Image references. They retain acquisition metadata from the source DICOM. Standalone RTSTRUCT therefore needs the derived primary images already imported at the destination. Bulk export with images includes both sets.

Registered secondary series in advanced ZIP retain their original acquisition geometry and pixels, with DICOM REG expressing their alignment. Destination TPS support and imported alignment must still be verified. Existing RTSTRUCT that references oblique native slices is not automatically remapped onto the axial reconstruction.

No assurance of dose-calculation suitability or clinical validation is implied by successful reconstruction. Interpolation cannot recover information missing from the acquisition, slice gaps, lossy compression or prior integer calibration.

## Verification

Synthetic tests cover a known physical intensity field, exact native voxel centers, fractional interpolation, LPS volume center, stable new UIDs, preserved originals, validity masks, memory limits, session round-trip, renamed-file reimport, compressed and headerless oblique sources, derived DICOM pixels/geometry and bundle references. Browser testing covers worker import, axial/MPR views, contour save/reopen and ZIP export. The user's specific prostate MRI has not been supplied for this test run.
